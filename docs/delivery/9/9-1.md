# [9-1] Operator-controlled starter content seed

[Back to task list](./tasks.md)

## Description

Stop auto-seeding demo catalog content into every new store. Make it a platform feature flag (default OFF) that the operator toggles from the platform-admin Features page, and give the operator a per-store "Seed starter content" action for stores that want it after the fact.

## Requirements

1. New registry flag `onboarding.starterContent` (group Onboarding, boolean, default `false`).
2. `initializeStoreSetup` skips the data-seeding step when the flag is off and records `steps.data_seeding = { status: "skipped", reason: "Disabled by platform feature flag", flag }`.
3. Default payment methods and the default header menu are still created — they are system defaults, not sample content.
4. `seedStarterContent(tenant, models)` is a reusable service; `seedStarterContentForTenant(tenantId)` records the outcome on the tenant's setup status.
5. `POST /api/platform/tenants/:tenantId/seed-starter-content` (scope `tenant.lifecycle`) triggers it; the platform-admin tenant page exposes it with a confirm dialog and shows the seeding step reason.
6. Tooling can force either behaviour via `initializeStoreSetup(tenant, models, { seedStarterContent: boolean })`.

## Implementation Plan

- `config/featureFlags.js` — register the flag.
- `services/storeSetup.js` — extract seeding, gate on `isFeatureEnabled`, export helpers.
- `controllers/platformAdmin.js`, `routes/platformAdmin.js` — seed endpoint.
- `platform-admin` — action button + reason display (see 9-3).
- `dashboard/src/lib/features.ts` — mirror the key.

## Test Plan

- Unit: `tests/unit/starterContentFlag.test.js` pins the registry contract and the key the pipeline gates on.
- Manual: register a store locally with the flag off → products collection empty, setup step "skipped"; flip flag → new store seeded; "Seed starter content" on an empty store → draft products appear and the merchant sees the publish banner.
