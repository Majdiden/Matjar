# [10-34] Theme categories managed from the platform console

[Back to task list](./tasks.md)

## Description

Signup's "What do you sell" step offered a fixed list of 8 niches (`config/storeNiches.js`, Register.tsx) and filtered the theme pick by raw manifest strings, while the merchant theme library used a different hard-coded list of 11 categories with aliases (`config/themeCategories.js`). Beauty, jewelry and health never showed at signup, and themes tagged "cosmetics", "kids", "decor" and so on never matched a niche.

Categories now live in the admin DB (`ThemeCategory { key, name: { en, ar }, icon, aliases, order, active }`). The platform owner creates, renames (en/ar), reorders, hides and deletes them on the console Themes page, and assigns each theme with chips (`Theme.categoryKeys`; `null` = automatic, derived from the manifest through the aliases). "General" is the catch-all: it can be renamed and moved but not hidden or deleted. Signup (`GET /api/themes/categories`) and the theme library (`GET /api/themes/active`) read the same list. `tenant.settings.niche` accepts the old niche ids or any active category key. Migration 017 seeds the union of both old lists ("kids" becomes "toys" to match the signup niche and theme presets) and records every theme's current categories.

## API

Platform (`/api/platform/storefront`, reads `support.read`, writes `flags.write` + 60/min per operator, every write audited):

- `GET /theme-categories`: all categories with `themeCount`, `protected`
- `POST /theme-categories` `{ key, name: { en, ar }, icon?, aliases?, active?, reason? }` (`theme_category.create`)
- `PATCH /theme-categories/:key` `{ name?, icon?, aliases?, active?, order?, reason? }` (`theme_category.update`)
- `PUT /theme-categories/order` `{ keys: [every key once], reason? }` (`theme_category.reorder`)
- `DELETE /theme-categories/:key` `{ reason? }`: also removes the key from theme assignments (`theme_category.delete`)
- `PUT /themes/:id/categories` `{ categoryKeys: [..] | null, reason? }` (`theme.categories.update`)
- `GET /themes`: rows carry `categoryKeys`, `categoryKeysManaged`; `meta.categoryOptions` comes from the DB

Public: `GET /api/themes/categories` → `{ categories: [{ key, name: { en, ar }, icon, order, themeCount }], themes: [{ slug, categoryKeys }] }` (active categories, owner's order). `GET /api/themes/active` themes carry `categoryKeys`; `categories` lists active categories that have themes.
