# [10-54] Notify stores: send to chosen stores, see who opened it

[Back to task list](./tasks.md)

## Description

**Send to:** all stores, or chosen stores. Stores are added one by one by search and shown as removable chips; "Clear all" empties the list. The server target is `tenants` with `tenantIds` (1–500). The one-store target `tenant` is kept for older messages. If any chosen store is inactive or missing, the send is refused.

**Who opened it**, shown in the history (unique people):
- **App:** people who read the notification, on the notifications page or by tapping the phone / desktop notification. Tapping now marks it read: the service worker adds `?notif=<id>`, and the dashboard marks it read and refreshes the count.
- **Email opened:** counted by a 1×1 tracking image (`/e/o/<token>`). This is an estimate: mail apps that block images never report an open, and Apple Mail privacy protection loads images for every message.
- **Email clicked:** the button goes through `/e/c/<token>`, which records the click (and the open) and redirects to the message's dashboard page on the app host.

**How tracking works**
- Tokens are HMAC-signed and name the message, the store and the person (`utils/announcementTracking.js`).
- The redirect target comes from the stored message, never from the URL, so the link cannot be used as an open redirect.
- A forged token still gets the image, or a redirect to the dashboard, but nothing is counted.
- `AnnouncementEvent` keeps one row per message, person and kind, so the counters are unique people.
