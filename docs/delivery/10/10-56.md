# [10-56] Currencies apply to the storefront: one store currency, shoppers pick a display currency

[Back to task list](./tasks.md)

## Description

Settings → Currencies had no visible effect on products. Two things were wrong:
1. The base currency was saved in `settings.currencies.base`, while the storefront, dashboard, emails and reports all read `settings.currency` (Settings → Regional). The two were never linked.
2. The exchange-rate currencies were only used by Markets at checkout (by shipping country). The storefront had no way to show prices in another currency.

**Changes**
- **One store currency.** Saving the base currency (Currencies tab) or the store currency (Regional tab) now writes both fields (`setStoreCurrency` in `controllers/settings.js`). A change must be in the platform's allowed base currencies. Migration `018_sync_store_currency` aligns existing stores: a store that saved the Currencies tab keeps the base it chose there; every other store keeps its Regional currency.
- **Rates the way merchants quote them.** The tab reads "1 USD = [600] SDG". The API still stores the multiplier (1/600), and the store currency is never listed as a rate.
- **Storefront.**
  - The store payload carries `currencyRates` (left out when there are none).
  - The language menu in every theme gains a "Currency" group, and the button shows e.g. "AR · USD". The choice holds for the visit.
  - `formatPrice` (all product, card, cart and search prices in all 18 themes) converts to the chosen currency.
  - With another currency chosen, the menu notes that prices are approximate and payment is in the store currency.
- **Charged amounts stay in the store currency:** checkout, order confirmation, order tracking, account orders, lifetime spend and gift-card balances use `formatBasePrice`.
