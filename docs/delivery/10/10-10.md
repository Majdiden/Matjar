# [10-10] Contact page from the brand kit

[Back to task list](./tasks.md)

## Description

A contact page the theme renders from the store's own data, so it always shows what the merchant has set: a big WhatsApp button, phone, email, address, city, opening hours and social pages. The merchant switches it on from the dashboard; when off, the existing contact page renders exactly as today.

## Requirements

1. Switch stored on the tenant: `settings.generatedPages.contact = true`; turning it off `$unset`s the key (absent = as before).
2. Storefront payload gains `generatedPages: { contact: true }` only when on; the key is absent otherwise (payload unchanged for every other store).
3. One shared implementation in `_shared`: `hooks/useContactInfo.ts` (`useContactInfo`, `useAutoContactEnabled`, `whatsappLink`, `telLink`, `pickBrandText`) and `pages/ContactPage.tsx`.
4. WhatsApp button: `https://wa.me/<digits>?text=<short message>` ("مرحبًا، لدي سؤال عن {{name}}" / "Hello, I have a question about {{name}}"). Phone from `settings.contact.phone` (tel: link), email, address; city and hours from the brand kit in the visitor's language (falls back to the other language); social pages from `store.socialLinks`. Each row only when set.
5. Routing is shared (`app/createThemeApp.tsx`), so every theme gets it: `/contact` and `/pages/contact` render `ContactPage` when the switch is on, otherwise `P.Contact` / `P.PageView` as before.
6. Dashboard `/dashboard/store/contact`: the switch plus a preview of what customers will see (from the same data), "Not added yet" for empty rows, a link to `/dashboard/store/brand`.
