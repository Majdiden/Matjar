# [10-14] Arabic-first bilingual field

[Back to task list](./tasks.md)

## Description

A reusable text field for simple mode: merchants write in Arabic, and English is always optional. Replaces the theme editor's side-by-side English/Arabic inputs in every simple-mode screen (first user: the brand-kit form, 10-12; next: the homepage simple editor, 10-13).

## Requirements

1. The Arabic input (`dir="rtl"`, `lang="ar"`) is always shown, in both dashboard languages.
2. A small "+ English (optional)" link reveals an English input (`dir="ltr"`); when the value already has English it is shown from the start; "Remove English" clears and hides it.
3. Supports one-line input and textarea, a per-language max length with a counter, and a required-Arabic message. English without Arabic is never accepted (same rule as the brand-kit API).
4. Errors show only after the merchant has left the field; outside (server) errors can be passed in.
5. A commit callback fires when focus leaves the whole field (not when moving between the two inputs) and the value is valid — the autosave hook point.
6. Each input shows an example in its own language (the caller passes `placeholder: { ar, en }`).
7. Clean, documented API for reuse by 10-13.

## Implementation Plan

- `dashboard/src/components/BilingualField.tsx` — component; API documented at the top of the file:
  - `value: { ar?, en? }`, `onChange(next)`, `onCommit?(value)`
  - `label`, `help?`, `labelAction?` (e.g. a "Saved" indicator), `placeholder?: { ar?, en? }`
  - `required?` (Arabic must be filled), `multiline?` + `rows?`, `maxLength?`, `error?`, `disabled?`, `id?`, `className?`
- `dashboard/src/lib/bilingual.ts` — `BilingualValue`, `validateBilingual(value, { required })` → `'ar_required' | 'en_only' | null`, `cleanBilingual(value)` (trim, drop empty English, null when empty), `sameBilingual(a, b)`. Kept out of the component file for fast refresh.
- Strings under `storeDesign:bilingual.*` (en + ar).
