# [10-8] Annotate themes (modern, starter first)

[Back to task list](./tasks.md)

## Description

Mark the settings the simple editor shows (`level: 'basic'`, at most 3 per section) and bind hero and contact settings to the brand kit (`bind`) on every theme, starting with `modern` and `starter`, without changing how any store without brand data renders.

## Requirements

1. `modern` and `starter` first, then the remaining 15 themes; at most 3 basic settings per section.
2. Hero: subheading → `brand.tagline`, background image → `brand.coverImage`; contact bits → `brand.whatsapp` / `brand.city` / `brand.hours` where such settings exist.
3. Bind the hero heading to `store.name` only if that does not change today's fallback.
4. Stores without brand data render exactly as before; the theme manifest contract test stays meaningful.

## Annotation rules used

- Basic settings, per section, in this order: the main text (`heading`, `heading_line1`, `title`, `message`, `text`, `quote`…), the supporting text (`subheading`, `body`, `body_text`, `description`…), then the main image (`background_image`, `image`…) or, when there is no image, the main button text. Toggles, colours, spacing, URLs, counts and layout choices stay advanced.
- Universal sections (`_shared/theme/universalSections.ts`, merged into every theme) are annotated once; `spacer` is an `advanced` section.
- Hero bindings: `subheading` → `brand.tagline` wherever a hero has one and renders it; `background_image` → `brand.coverImage`. Theme heroes whose image is a product cut-out in a split layout (`glowing`, `milmaa`, `nutreko`, `beauxe`, `aurum`) keep their image unbound — a wide cover photo would not fit there.
- `starter`, `artisan`, `bookshelf`, `freshmart`, `homedecor` and `kidsworld` heroes already render `hero.background_image` but did not declare it. They now declare an optional `background_image` (no default, so an unconfigured store still gets `undefined`) bound to the cover photo.
- `store.name` is bound nowhere: every hero heading falls back to translated theme copy (e.g. modern `theme.section.hero.headline`), not the store name, so a binding would change unconfigured stores. `store.logo`: no theme has a logo setting.
- Contact: `techhub` hero top strip `hotline_phone` → `brand.whatsapp` (its fallback was a demo `+1 (555) 456-7890`); `linen` theme-level `opening_hours` → `brand.hours` (footer). `atelier` `hotline_phone` is left unbound: its fallback is the store's contact phone, which the WhatsApp number should not replace. No theme has a city setting.
- `atelier` builds most sections from a `headingGroup()` helper; the helper marks heading + subheading basic, and five sections add their main image.

## Implementation Plan

- Mechanical pass with a throw-away script over `src/theme.manifest.ts` (rules above, per-theme exceptions by hand), keys placed after `label`.
- Validation is enforced at build time (`scripts/validate-theme.js` → `validateManifestExtensions`) and in two new contract-test checks per theme.

## Test Plan

- Build every theme; `scripts/validate-theme.js` must pass.
- Compare each built `dist/manifest.json` with the pre-change build after stripping `level`, `bind`, `presets` and the build stamp: identical except the 6 added hero `background_image` settings.
- `tests/unit/theme-manifest-contract.test.js` (now also: annotations valid, the home page has at least one basic setting) and the "unconfigured store unchanged" pin in `tests/unit/themeBindings.test.js` (every built theme).
- Typecheck the changed themes.
