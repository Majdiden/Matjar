# [10-47] Beta invitation codes, the Promoter role and the signup lock

[Back to task list](./tasks.md)

## Description

Signup during the beta can require an invitation code. Codes are made in the platform console by the owner and by a new **Promoter** role; each code registers one store.

- **Signup lock** (owner only, Invitation codes page): *Open* (no field), *Referral code* (optional field "Referral code / رمز الإحالة (اختياري)"), or *Beta invitation code* (required field "Beta invitation code / رمز الدعوة للفترة التجريبية"). The field sits on the signup step where the store name and link are entered, is filled in from a shared link (`/dashboard/register?code=…`) and is checked while typing (`GET /auth/check-invitation-code`, rate limited). A given code must be valid in both code modes. Adding another store from an existing account never asks for a code.
- **Codes** (`InviteCode`, admin DB): 8 unambiguous characters shown as `XXXX-XXXX`, an optional note, created/used/revoked timestamps and the store that used it. Signup claims the code atomically (one store per code, even under concurrent signups) and gives it back if creating the store fails; the store records the code and its promoter (`Tenant.inviteCode`). Unused codes can be revoked.
- **Invitation codes page**: stats (codes created, stores registered, unused, revoked — only the viewer's codes), create 1–20 codes, the list with code, note, status, created and used times and the registered store, copy code / copy signup link / revoke. The owner sees everyone's codes, who created each and can filter by person.
- **Promoter role** (scope `invite_codes.manage`, held by owner and promoter only — not admin): invited by email through the existing platform-user invitation and signs in with the normal platform login. A promoter's console shows only the Invitation codes page and, for stores registered with their codes, a store page reduced to the header (name, link, email, phone, refresh), the users and products counts and the Overview tab's Setup, Domains and Data cards. Every other platform endpoint refuses them (checked by a test that calls every platform GET route); other pages redirect to their codes; another promoter's store answers "not found".
- The store page's Setup, Domains and Data cards moved to `components/tenant/OverviewCards.tsx`, shared by both store pages.
