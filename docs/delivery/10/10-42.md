# [10-42] Two-language fields: the UI language first, one language per box

[Back to task list](./tasks.md)

## Description

On every dashboard form with per-language fields, the field in the current UI language comes first (Arabic first in the Arabic dashboard, English first in the English one), each box types in its own direction, and each box holds exactly one language.

- Shared, dependency-free rules in `dashboard/src/lib/languageOrder.ts` (+ `useLanguageOrder`): order by UI language; load each box from `translations.<lang>` or, for older data, from the base value when it is written in that language (quick-add put Arabic in the base, older forms put English there, seeded menus put the store language there); save both translations explicitly and the store-language text (or the other one when empty) in the base.
- Product form (name, short description, description), content sections, categories and menus (all levels) use it; the store-language box carries the required mark and the error; either language is enough. BilingualField (brand kit, homepage, policies, About) and theme-editor `__ar` twins follow the same order.
- Backend: content sections accept and store `translations.en`.
