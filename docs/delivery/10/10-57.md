# [10-57] Price in one currency, sell in another; optional currency switcher

[Back to task list](./tasks.md)

## Description

Merchants want to enter prices in a stable currency (e.g. USD) and show and charge visitors in the local one (e.g. SDG), with their own exchange rate. Showing a currency switcher should be optional.

**Settings → Currencies**
- **Pricing currency (`currencies.base`, = `settings.currency`):** product prices, shipping fees and discounts are entered in it, and the dashboard shows it.
- **Exchange rates:**
  - Each row reads "1 USD = 600 SDG".
  - ⇄ flips the direction, and stored rates are shown the way round that gives a number of 1 or more.
  - Rates are stored as the multiplier from the pricing currency.
- **Website currency (`currencies.display`, null = the pricing currency):** what visitors see and pay in. It must have a rate, otherwise the save is refused with 400.
- **"Let visitors change the currency" (`currencies.showSwitcher`):** adds the currencies to the language menu. Off by default; when off, everyone sees the website currency only.

**Storefront**
- `store-info` carries `currency` (pricing currency), plus `displayCurrency`, `currencyRates` and `currencySwitcher` only when they are needed.
- `formatPrice` converts every price into the visitor's currency.
- Checkout and gift cards use the website currency (`formatChargedPrice`).
- Placed orders use the order's own currency and rate (`formatOrderPrice`). The tracking API now returns `baseCurrency`, `presentmentCurrency`, `presentmentTotal` and `fxRate`.
- Price filters typed in the visitor's currency are converted to the pricing currency in the shared API client (all themes).

**Checkout and orders**
- With no market for the buyer's country, the website currency becomes the presentment currency. The order keeps pricing-currency amounts plus `presentmentCurrency`, `presentmentTotal` and `fxRate`.
- The dashboard order page shows "Customer pays SDG …".
- The order emails' `{{total}}` is the customer's amount.
