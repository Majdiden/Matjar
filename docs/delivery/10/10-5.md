## Requirements

1. `buildStoreInfo` adds `brand`: the public subset (tagline, coverImage, color, whatsapp, city, hours) with only non-empty, valid values, or `null` when nothing is set.
2. The fetched (`GET /storefront/store-info`) and embedded (SPA shell) payloads stay identical — both use `buildStoreInfo`.
3. `@matjar/theme-shared`: `BrandKit`/`BrandText` types on `StoreInfo` (both the context and the commerce type) and `useBrand()` next to `useStore()`, exported from the package index.
4. Themes do not use it yet — no visual change.
5. Feature flag `design.simpleMode` (boolean, default off, group Storefront, "Simple store design (brand kit)") in `config/featureFlags.js`, mirrored in `dashboard/src/lib/features.ts`. The API is not gated.

Out of scope here: the brand colour feeding the theme's primary token (needs the value-resolution rules of 10-7, so that unconfigured stores stay unchanged).

## Implementation Plan

- `services/storefrontStoreInfo.js`: `brand: publicBrand(tenant.settings?.brand)`.
- `storefront-themes/_shared/types/commerce.ts`, `contexts/StoreContext.tsx`, `index.ts`: types + `useBrand()`.
- `config/featureFlags.js`, `dashboard/src/lib/features.ts`: flag + mirror.

## Test Plan

- Unit (`tests/unit/storefrontStoreInfo.test.js`): `brand` is null when unset or all-empty; only valid non-empty public fields are exposed (invalid cover URL, empty text and unknown keys dropped; colour lowercased); JSON round-trip equal.
- Unit (`tests/unit/brandKit.test.js`): flag registered, boolean, default off, mirrored in the dashboard list.
- E2E (`tests/e2e/store-profile.test.js`): store-info shows `brand: null` before and the saved brand kit after a PUT; another store stays `null`.
- Static: dashboard `npx tsc -b`; theme-shared typecheck.
