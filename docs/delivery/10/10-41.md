# [10-41] Signup asks for the store identity instead of the location

[Back to task list](./tasks.md)

## Description

Signup v2 (10-16) asked for the city and delivery areas, which made signup longer without making the store feel like the merchant's; the guided setup already asks for delivery areas in its "Delivery and returns" step. Signup now collects the store's identity so the store already looks like theirs when signup ends:

- **Store step:** name, a short line (optional, shown under the name) and the store link.
- **New identity step:** logo (gallery or camera), colour and cover photo — all optional, one screen. The colour of the logo is suggested and selected first (`dominantColor`), followed by ten ready-made colours; the cover photo replaces the theme's sample picture.
- **Location step removed.** City is optional in Site identity; delivery areas are asked in the guided setup.

The short line and colour go with the signup request (`tagline`, `brandColor`, validated; an English signup fills both languages of the short line because the brand kit needs Arabic). The logo and cover photo can only be uploaded once the store exists: signup keeps the shrunk files in memory (`lib/signupIdentity.ts`) and the setup screen uploads them with the new store's token right after creation, before signing in (`lib/signupIdentityUpload.ts`; add-a-store does the same with its new token). Failures never block signup — the guided setup asks again.
