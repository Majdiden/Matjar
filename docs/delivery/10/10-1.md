# [10-1] Forgiving store-link field + general share button

[Back to task list](./tasks.md)

## Description

Make signup's store-link (subdomain) field work for merchants who don't know what a subdomain is, and replace the WhatsApp-only share button with a general share button.

Observed in production: merchants pasted their Facebook page URL into the field, and then pasted our example `https://store-name.matjar.to` verbatim. An Arabic-only store name gave an empty link.

## Requirements

1. An Arabic (or mixed) store name produces a valid suggested link by transliteration (Sudanese everyday spelling, e.g. ق → g). Arabic-Indic digits and diacritics are handled.
2. Pasting into the store-link field is interpreted, not filtered character by character:
   - Our own link (`nile.matjar.to`, with or without scheme/path) → the name part.
   - Our example copied verbatim (`store-name`, `https://store-name.matjar.to`, …) → ignored; the link is suggested from the store name.
   - Facebook / Instagram / TikTok / Telegram / X page → URL kept as a social link; link suggested from the page name when there is one.
   - WhatsApp link → explained, nothing stored.
   - Any other website → link suggested from its name.
3. The same detection runs for keyboards that insert clipboard text without a paste event.
4. A link pasted into the store-name field is not used as the name; a social page is kept.
5. Each reinterpretation shows a one-line plain-words notice. The field has help text and shows "Your store will open at: https://…".
6. Typed input is sanitised as you type (spaces/dots → hyphen, Arabic transliterated) and tidied on blur (edge hyphens, typed `https-`/`www-`/`-matjar-to` leftovers).
7. Recognised social links are sent with register / add-store and stored in `tenant.settings.socialLinks`. The server accepts only https URLs on each platform's own hosts (400 otherwise, before any write) and never exposes empty or invalid entries to themes.
8. The store-live banner's share button opens the native share sheet when available (any app), else a menu with WhatsApp, Facebook, Telegram and Copy link.
9. All new Arabic copy follows the PRD copy guideline (plain, natural Arabic; not dialect and not literal translation).

## Implementation Plan

- `utils/socialLinks.js`: platform → host allowlist, `normalizeSocialLink(s)`, `publicSocialLinks`.
- `schemas/tenant.js`: `settings.socialLinks.{facebook,instagram,tiktok,telegram,x}`, no defaults.
- `validators/auth.validator.js`: optional strict `socialLinks` object.
- `services/tenant.js`: normalise before any write, 400 on invalid; `controllers/auth.js` passes it for add-store.
- `services/storefrontStoreInfo.js`: expose only `publicSocialLinks(...)` (themes render every entry they get).
- `dashboard/src/lib/storeLink.ts`: pure helpers (transliteration, slugify, typing sanitiser, blur tidy, link interpretation, inserted-text diff).
- `dashboard/src/pages/Register.tsx`: paste/insert handling, notices, help + preview, `socialLinks` in both submit paths.
- `dashboard/src/lib/share.ts` + `dashboard/src/components/ShareButton.tsx`; `LiveStoreBanner.tsx` uses it.
- i18n: `auth.field.subdomain.*`, `auth.field.store_name.*`, `auth.social.*`, `common.share.*` (en + ar).
