# [10-39] Store colour, no stock flash, featured only when featured, phone wishlist

[Back to task list](./tasks.md)

## Description

Merchant feedback on the storefront themes:

- **Store colour.** The identity colour from My store only replaced the primary token (buttons, links), so stores did not look like the merchant's. `_shared/theme/brandColor.ts` derives `--brand`, `--brand-contrast` (readable text on it), `--brand-strong`, `--brand-soft` and `--brand-ink` (readable on white); ThemeProvider writes them only when the store has its own colour. Every theme paints its signature areas with them — top strip, header/footer bands, hero panels, accent sections, badges, the active phone-menu pill — falling back to its own colours, so stores without a colour are unchanged. `--color-on-primary` gives readable text on the primary colour for shared buttons and badges.
- **Stock flash on refresh.** The store details were already embedded in the page; the flash came from heroes, collages, collection banners and category tiles that showed stock photos and demo names while products and categories loaded, then swapped. They now show a plain panel of the same size until the data arrives, then the merchant's or the store's own pictures (stock only for a store with none).
- **Featured products.** Featured / best-seller grids render nothing while loading or when no product is featured (no fallback to other products under a featured heading). Techhub's flash-deal card hides when nothing qualifies instead of loading forever.
- **Wishlist.** Every theme's phone header has a heart to /wishlist with a count (`WishlistHeaderLink`).
