# [10-9] About page from questions

[Back to task list](./tasks.md)

## Description

The merchant answers a few short questions (what they sell, since when, where, what makes them different, an optional photo) and we write the About page for them in plain Arabic, plus English when they give English answers. The answers are stored so the text can be rebuilt; a page the merchant later rewrites by hand is never replaced without asking.

## Requirements

1. Questions (Arabic first, English optional): `products` (required), `since` (year, optional), `city` (optional, prefilled from the brand-kit city), `different` (optional), `photo` (optional, picked from the media library; `https://` or `/uploads/...` only).
2. Output: one `about` Page per language — Arabic always, English only when "what do you sell" has English. An English sentence whose answer has no English text is left out (no mixed languages). Pages are published.
3. Templates are named constants (`ABOUT_TEMPLATES` in `services/generatedPages.js`); every answer is HTML-escaped, then the page goes through `utils/sanitizePageHtml.js` like any page.
4. Answers stored additively on the Page: `generator = { kind: 'about', answers, generatedAt, edited }`.
5. A hand edit (title or content changed through `/api/pages/:id`) sets `generator.edited = true`. Saving answers over an edited generated page, or over a hand-made non-starter About page, returns 409 `GENERATED_PAGE_EDITED` until resent with `overwrite: true`. Starter (demo) pages are replaced freely.
6. Removing the English answers deletes the generated English page unless it was edited.
7. Storefront picks the visitor's language: `usePage` sends `?lang=`; the server returns that locale's visible page and otherwise falls back to the old lookup (stores with one page per slug get the same page as before).

### API

```
GET /api/store-pages/about            (themes.read | themes.write)
PUT /api/store-pages/about            (themes.write)
body: { "answers": { "products": {ar, en?}, "since"?: 2019, "city"?: {ar, en?},
                     "different"?: {ar, en?}, "photo"?: "/uploads/..." },
        "overwrite"?: true }

200 { success, data: {
  answers: {...} | null, generatedAt: Date | null,
  edited: boolean,                      // saving would replace hand-written text
  pages: [{ id, locale, title, isPublished, generated, edited }],
  suggestions: { city: {ar, en?} | null }
} }
400 bad answer (field in errors[0].field) · 401 · 403 · 409 { code: "GENERATED_PAGE_EDITED" }
```

## Implementation Plan

- `services/generatedPages.js` (new, pure): templates, `normalizeAboutAnswers`, `buildAboutPage`, `aboutLanguages`, `escapeHtml`.
- `services/storePages.js` (new): `getAboutService`, `saveAboutService` through `repositories/page.js` (`listPagesBySlugRepo` added) and `repositories/tenant.js`. Page writes are idempotent, so no transaction (a partial failure is fixed by saving again).
- `services/page.js`: mark `generator.edited` on a real title/content change.
- `schemas/store/page.js`: optional `generator` sub-document (no default).
- `controllers/page.js` + `_shared/api/client.ts` + `_shared/hooks/usePage.ts`: `?lang=` preference.
- Routes/controller/validator: `routes/storePages.js`, `controllers/storePages.js`, `validators/storePages.validator.js` (audit `pages.about.generated`).
- Dashboard `/dashboard/store/about` (`pages/store-design/StoreAbout.tsx`, `AnswerField.tsx`, `StoreScreen.tsx`), behind `design.simpleMode` + `themes.write`; strings in the new `storePages` namespace.

## Test Plan

- Unit (`tests/unit/generatedPages.test.js`): Arabic from all answers; English only from English answers with no Arabic leaking; missing optional answers drop their sentence; XSS in every answer and the store name is escaped; bad answers rejected.
- E2E (`tests/e2e/store-pages.test.js`): generate ar+en, published, escaped; storefront `?lang=ar|en`; dropping English removes the page; hand edit → `edited`, 409 without overwrite (content untouched), overwrite rewrites; 8 bad bodies → 400 with nothing written; hand-made About page protected; staff 403 / manager 200 / no token 401; cross-tenant isolation; `?lang=` returns the same page as before for a single-locale store.
