# [11-1] Permanent store deletion (single + bulk) with owner-granted permission

[Back to task list](./tasks.md)

## Description

Add a platform-console action that permanently deletes stores (from the store page and as a bulk action), visible only to staff holding `tenant.delete`. Owners hold it by default, and other staff only if an owner grants it. Every use requires the operator's password. See the [PRD](./prd.md) for the design.

## Requirements

1. New scope `tenant.delete`: OWNER by role, excluded from every other role, grantable or revocable per person by an owner (re-auth required).
2. Single endpoint and bulk endpoint, each gated by the scope, body validation and password confirmation.
3. Single deletion needs the store's slug typed back and a reason. Bulk deletion needs "delete N stores" and a reason, with at most 20 stores.
4. Deletes the store completely (see the PRD for the order and what is retained), resumably.
5. Audit row per store plus a bulk summary row, and an owner email alert.
6. Replaces the console "Purge" action, which was owner-only, partial and unavailable for archived stores. The grace-period sweep keeps its archive behaviour but now wipes every store collection.

## Test Plan

- E2E `tests/e2e/tenant-permanent-delete.test.js`:
  - Owner deletes a store: wrong password or slug change nothing; afterwards every row is gone, other stores and staff are intact, the hostname is free, and the audit row exists without the password.
  - Admin and operations users are denied.
  - Grant and revoke are owner-only, need re-auth, take effect immediately, and can't target owners.
  - Bulk deletion: count phrase and password are enforced; per-store results; a missing store doesn't stop the others.
- Unit `tests/unit/tenantDeletion.test.js`: storage prefixes never cover the base folder or a path, local paths can't escape the uploads root, the wipe refuses invalid ids, and the bulk phrase and cap are pinned. `tests/unit/platformRoles.test.js`: only the owner role holds `tenant.delete`, and explicit grants work.
- Static: platform-admin `tsc -b` and eslint on changed files.
- Visual: tenants bulk bar and bulk-delete dialog, staff page badge and grant dialog (mocked API, headless Chrome).
